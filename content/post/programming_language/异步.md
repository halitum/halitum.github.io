# 异步小记

异步编程是一种程序执行方式，主要目的是解决I/O密集型任务中频繁出现的阻塞导致程序耗时过长，CPU不能被充分利用的问题。

---

**异步的程序执行流程是怎样的？**

想象一家沙县小吃店，你走进餐馆，和服务员点餐，这等同于启动了一个任务。之后服务员走到厨房把你点的餐告诉厨师。如果这个服务员是同步的，那他就会站在厨师旁边等待，直到厨师把你的饭做好，服务员才会端着你的饭从厨房里出来递给你，然后才为下一桌客人服务。这个点单的任务就类似一个IO密集型任务，他耗时很长，但又不占用CPU，而这种情况下称为厨师做饭产生了阻塞，服务员点单和厨师做饭之间产生了一个依赖关系。

第二天你走到了另一家沙县小吃店，这家店的店员非常聪明，每当他将订单告知厨师之后就会回头接着为下一桌客人点单，直到厨师把你的餐做好之后才会回到厨房把你的餐端给你，这就是一个异步程序的执行流程。这里我们将服务员视为一个主程序，或者事件循环，厨师做饭视为一个协程，当阻塞产生之后，协程就会立刻放权，让主程序执行事件循环里的下一项任务。

> 需要补充的一点是，这个主程序也可以被视为一个协程，因为主程序中的任务也会被暂停和恢复。

服务员又如何知道厨师什么时候将你的饭做好了？当服务员向厨师发起任务时，会同时交给厨师一个回调函数callback，厨师使用回调函数记录自己任务的执行情况，而服务员也能通过回调函数来得知你的饭有没有被做好。

---

**什么是协程coroutine？**

协程就是一个程序实例，或者说就一个函数，他的特点是可以被暂停运行和恢复运行。

python中，coroutine 由 asyncio 的 async def 定义

```python
import asyncio

async def a_coroutine_function():
    pass
```

协程函数的特点是，调用协程时，程序不会被真的运行，而是返回一个协程对象

```python
async def a_coroutine_function:
    return 'This is a coroutine function'
print(a_coroutine_function())

# <coroutine object coroutine-function at ex10130b3d>
```

只有运行协程对象时，才会运行其中的代码

协程可以在出现 await 时被暂停运行，将控制权交还事件循环：

```python
async def a_coroutine_function:
    await asyncio.sleep(1)
```

await 中的程序完成后，程序会再向事件循环请求控制权，来恢复运行（ps：能被 await 的程序也必须是一个协程）。没有控制权的程序只能等待

---

**什么是事件循环？**

事件循环用来调度多个协程的执行，这一点是通过调度控制权来实现。在协程运行时，事件循环做三件事

- 检查协程：拿到控制权之后检查有没有可以执行的协程
- 让出控制：将控制权交给可以运行的协程
- 等待协程：在协程终止或暂停时收回控制权
  （之后就会回到第一步检查携程）

一个协程会被包装成任务，来方便事件循环的调用和检查。任务包含了协程自身和协程的状态信息

> 语法糖：await
>
> - 暂停当前协程
> - 将 await 后面的协程包装为任务
> - 获取 await 后的协程结果

python中，使用 asyncio.run()等方式建立事件循环

*asyncio的to_tread方法可以在新线程中执行同步函数，同时不阻塞事件循环*

```python
def blocking_task(name):
    time.sleep(2)  # 假设是一个阻塞操作
    return f"{name} 任务完成"

async def main():
    print("开始异步任务")
    result = await asyncio.to_thread(blocking_task, "下载文件")
    print(result)

asyncio.run(main())
```

**扩展：进程、线程**

进程是一个程序运行的实例，被存放在内存中

![image-20250324013702723](https://typora-picturelib.oss-cn-beijing.aliyuncs.com/image-20250324013702723.png)

线程是比进程更细粒度的单位，也是程序执行的最小单位，一个进程可以由一个线程运行，也可以由多个线程运行。![image-20250324013730664](https://typora-picturelib.oss-cn-beijing.aliyuncs.com/image-20250324013730664.png)

每条线程都可以使用一个不同的CPU核心来运行，从而更好地利用CPU的多核性能。（但在python中，由于全局解释器锁GIL的限制，同一时间只能有一个线程执行 Python 字节码，因此python的多线程是通过在一条线程中分时段同时运行多个任务来模拟出来的）

***python 高级线程池库 ThreadPoolExecutor***

线程池是一种享元模式的实现。享元模式参考文章：【[享元模式与对象池](https://www.hell-0.xyz/p/享元模式与对象池/)】

ThreadPoolExecutor 是 python 官方对 treading 操作做了高级封装的库

```python
from concurent.futures import ThreadPoolExecutor

def a_waste_time_func(*args, **kwargs):
    pass

# 初始化线程池对象
t = ThreadPoolExecutor(max_worker=n)  # 可以指定最多使用几个线程（调用堆栈中可以看到每个线程的运行状况）

t.submit(a_waste_time_func, *args, **kwargs)  # 会将程序交给线程池中的线程来运行，而主线程可以继续往下运行

print('立刻就运行完成了！')
```

线程池使用完成后需要手动关闭

```python
t.shutdown()
# 参数
#   cancel_future: bool=False
#	  执行shutdown()方法时是阻塞主线程还是直接关闭线程池中的所有线程。默认阻塞
```

线程池对象也可隐式申明

```python
with ThreadPoolExecutor() as t:
    t.submit(...)
# 这种实例化的t是阻塞的
```

获取线程执行的函数的返回值

```python
threads = []
threads.extend([t.submit(...), t.submit(...), ...])
# 这里封装了线程安全等功能
# 依次获取每个线程执行的结果
for thread in threads:
	print(thread.result())
# 每当一个线程执行完就获取结果
from concurrent.futures import as_aompleted
for thread in as_completed(threads)
	print(thread.result())
```
